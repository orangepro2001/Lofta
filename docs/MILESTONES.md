# 正式开发里程碑

闸门通过前不开工。闸门条件见 `PROGRESS.md`。每个里程碑都是可玩版本，开工前写 `docs/M<N>.md`，完工后写 `docs/handoff-M<N>.md`。

| 里程碑 | 内容 | 门槛 |
| --- | --- | --- |
| M1 第一章可玩切片 | 1 张等距图，5 名人物，12 时段，14 张卡，6 个配方（含 2 个谬误），一场 3 轮对质，存读档，45 至 60 分钟 | 机器人脚本通关；8 名新人中至少 6 人碰到谬误后能自己说出错在哪 |
| M1.5 灰盒 | 不超过 20 张卡的 30 分钟小案，跑通案例表、反驳变灰、按来源看牌、一夜路线，不要美术 | 5 名新人中 4 人能说出三个动词的区别 |
| M2 美术方向 | 等距建筑风格、人物动画、昼夜灯光、天气、界面定稿 | 第一章全部场景截图通过审查 |
| M3 声音 | 程序合成的环境声、钟声、脚步、界面音 | 一段完整流程无卡顿爆音 |
| M4 第二、三章 | 新地图、归纳和反驳机制、缺席表界面 | 第三章末的推理可解，试玩者不靠提示能走完 |
| M5 第四章 | 一夜时段规划、午夜钟声演出 | 三种路线都测过 |
| M6 第五、六章 | 法庭对质、溯源和弃用来源 | 第六章的“认出老塔克”能靠线索完成 |
| M7 第七章与结局 | 终局对话、六个结局、真实总账画面 | 六个结局都有机器人路线 |
| M8 打磨与发布 | 全流程校对、性能、签名问题解决、发布 | beta 渠道可更新 |

## 不做什么

- 不做战斗、属性、技能树、背包重量。
- 不做配音。
- 不做英文版。
- 不做网页和手机版。
- 不做 Mod 接口。
- 不做程序生成的伦敦，全部地图手写。
- 第一轮不做手柄。

## 风险

| 风险 | 对策 |
| --- | --- |
| 内容量失控 | 对白以 `content/` 现有文本为上限，新增内容要删旧内容 |
| Defender 误报挡住分发 | 见 `RELEASE.md`，M8 前必须解决 |
| 手绘地图工作量大 | 用 ASCII 地图加程序生成细节，建筑做成可复用的模块 |
| 谜题实际上太难或太易 | 试玩是最大瓶颈，推理游戏的试玩者看过就废。分配：第 1 章 8 人；第 3、4、6 章各 5 人；第 2、5、7 章各 3 人 |
| 时段系统让人焦虑 | M1 试玩重点观察，可调预算 |
